# 歌单清单转换工具需求文档

## 1. 文档信息

- 项目名称：歌单清单转换工具（暂定）
- 文档状态：初版，待用户确认
- 当前目标版本：MVP 1.0
- 产品形态：响应式网页，后续可扩展为 PWA
- 目标平台：QQ 音乐、网易云音乐

## 2. 产品背景

用户可能从聊天记录、文章、AI 推荐结果或其他音乐平台获得一份格式不统一的歌曲清单，例如：

~~~text
1、龙卷风 周杰伦
2、夜曲
3. 演员 - 薛之谦
~~~

用户希望将这类清单整理为目标音乐软件官方导入功能可识别的内容，减少逐首搜索和手工录入成本。

第一版不直接登录或操作用户的 QQ 音乐、网易云音乐账号，不播放、下载或代理音频，也不绕过会员、地区和版权限制。系统只处理用户主动提交的歌曲文字元数据，并生成可复制或下载的导入内容。

## 3. 产品目标

### 3.1 MVP 目标

1. 支持输入包含歌名且歌手可能缺失的歌曲清单。
2. 识别常见序号、分隔符、歌手和版本信息，将输入转换为结构化歌曲条目。
3. 允许用户逐条检查、编辑、删除、排序和去重。
4. 按目标平台生成经过验证的官方导入格式文本。
5. 支持一键复制和下载 TXT 文件。
6. 不要求注册、登录或提交音乐平台 Cookie。
7. 默认不在服务端持久化用户的原始歌单内容。

### 3.2 成功标准

1. 对规范输入 `歌名 - 歌手` 的字段识别准确率达到 100%。
2. 对需求文档列出的常见输入格式，歌曲边界识别准确率达到 95% 以上。
3. 低置信度或缺少歌手的条目必须被明确标识，不得静默伪造歌手信息。
4. 用户可以在不登录本站的情况下完成“输入—校对—导出”完整流程。
5. 导出内容在发布前经过对应音乐客户端的人工导入验证。
6. 单次处理 500 首歌曲时，页面仍可正常编辑和导出。

## 4. 用户与使用场景

### 4.1 目标用户

- 从文章、聊天或 AI 回答中获得歌曲清单的用户。
- 需要整理格式混乱歌单的用户。
- 希望在 QQ 音乐或网易云音乐官方导入功能中继续操作的用户。
- 不愿向第三方网站提供音乐账号、Cookie 或密码的用户。

### 4.2 核心场景

#### 场景 A：文字清单转 QQ 音乐导入内容

用户粘贴歌曲清单，系统完成解析，用户校对后选择 QQ 音乐并复制导入文本。

#### 场景 B：文字清单转网易云音乐导入内容

用户粘贴歌曲清单，系统完成解析，用户校对后选择网易云音乐并生成导入内容。发布前必须验证网易云音乐当前客户端实际支持的导入方式；若不支持纯文本导入，不得宣传为“官方文本导入”。

#### 场景 C：修正不完整清单

输入只有歌名或存在歧义时，系统标记为“待确认”，用户可以补充歌手、版本或删除该条目，然后再导出。

## 5. MVP 范围

### 5.1 包含范围

- 多行文字粘贴。
- 常见序号和分隔符识别。
- 歌名、歌手、版本字段解析。
- 解析置信度和异常提示。
- 条目编辑、删除、拖动排序。
- 重复歌曲识别和用户确认去重。
- QQ 音乐导出适配器。
- 网易云音乐导出适配器；是否可标注为“官方可导入”取决于发布前实测。
- 一键复制。
- UTF-8 TXT 下载。
- 本地草稿恢复，可由用户主动清除。
- 基础隐私说明、使用说明和免责声明。
- 桌面端与移动端响应式布局。

### 5.2 明确排除范围

- 注册、登录、用户中心和云端历史记录。
- QQ 音乐或网易云音乐账号登录。
- 接收或保存账号密码、Cookie、Token、二维码登录态。
- 直接创建、修改、收藏或删除平台歌单。
- 音频播放、试听、下载、转码、代理和播放地址解析。
- 歌词、专辑封面、MV 等受版权保护内容的抓取或展示。
- 绕过会员、地区、数字专辑或版权限制。
- 使用逆向接口或模拟客户端私有协议。
- 收藏数、点赞数、评论数的抓取。
- 会员歌曲优先或非会员歌曲过滤的结果保证。
- QQ 音乐与网易云音乐公开歌单链接的自动解析。
- 截图 OCR。
- 管理后台、数据库、Redis、消息队列。
- 原生 App、桌面客户端和浏览器扩展。

### 5.3 后续候选范围

以下能力仅作为路线图，不属于 MVP 承诺：

1. 在取得正式授权后使用平台搜索接口补全歌手、专辑和版本。
2. 在合法数据可用的前提下提供会员可播放范围筛选。
3. 在平台正式接口提供对应指标时，以收藏数、点赞数、评论数作为同一歌曲候选的次级排序。
4. 通过官方或明确允许的公开接口解析公开歌单链接，实现跨平台清单转换。
5. 生成高清歌单图片，适配官方截图导入功能。
6. PWA 安装、系统分享入口和离线解析。
7. Python OCR 或文本模型服务。

## 6. 业务规则

### 6.1 输入要求

1. 每条歌曲必须包含歌名。
2. 歌手、作者、专辑和版本信息均可缺失。
3. 系统不得把无法可靠判断的字段伪装为已确认结果。
4. 前端必须在提交前提示空输入、超长输入和无法识别的行。
5. 第一版验收容量为单次最多 500 个非空条目；技术限制应通过配置维护。

### 6.2 支持的首批格式

~~~text
1、龙卷风 周杰伦
2. 夜曲 - 周杰伦
3) 演员—薛之谦
4  稻香	周杰伦
晴天
~~~

需识别的序号形式至少包括：

- 阿拉伯数字加 `、`、`.`、`)`、`）`；
- 行首数字加一个或多个空格；
- 无序号纯文本行。

需识别的分隔符至少包括：

- ` - `；
- ` — `；
- Tab；
- 两个及以上连续空格；
- 具有明确解析规则的单个空格。

单个空格不能无条件视为歌名和歌手分隔符。无法可靠判断时保留整行歌名并标记待确认。

### 6.3 标准化规则

1. 使用 Unicode NFKC 进行字符标准化。
2. 统一全角和半角标点。
3. 删除行首序号，不删除歌名内部数字。
4. 清理首尾空白，合并无业务含义的重复空白。
5. 保留原始行文本，便于用户回看和纠错。
6. 识别但不擅自删除 `Live`、`Remix`、`DJ`、`伴奏`、`纯音乐`、`翻唱`等版本标记。
7. 多歌手字段默认保留输入顺序。

### 6.4 歌手缺失规则

1. 第一版不通过非官方平台接口自动猜测歌手。
2. 缺少歌手时，状态为“信息不完整”。
3. 用户可以手动补充歌手，也可以选择仅按歌名导出。
4. 导出前页面应提醒：仅歌名条目更容易在官方导入时匹配到错误版本。

### 6.5 去重规则

1. 默认不自动删除重复项。
2. 完全相同的标准化歌名和歌手标记为“疑似重复”。
3. 歌手缺失时，仅歌名相同不能直接自动去重。
4. 用户可以单条删除或批量确认去重。
5. 去重后保留第一次出现的位置和顺序。

### 6.6 排序规则

1. 默认保持输入顺序。
2. 用户编辑和删除操作不能导致其他条目意外换序。
3. 允许拖动调整顺序。
4. 第一版不提供按热度自动排序。

### 6.7 导出规则

1. 导出器按目标平台隔离实现。
2. 输出默认每行一首歌曲。
3. 推荐的标准输出为 `歌名 - 歌手`。
4. 缺少歌手时仅输出歌名，不补写未知占位符。
5. 输出必须使用 UTF-8 编码和 LF 换行；下载文件可根据客户端兼容性增加 UTF-8 BOM，但必须通过实测决定。
6. 导出前显示文本预览和条目数量。
7. 复制和下载不得改变歌曲顺序。
8. 平台导入格式若发生变化，应通过独立导出器和配置适配，不修改核心解析数据。

## 7. 页面需求

### 7.1 首页与输入页

包含：

- 产品说明；
- 大文本输入框；
- 支持格式示例；
- “开始整理”按钮；
- 隐私提示；
- 本地草稿恢复入口；
- 清空草稿入口。

交互要求：

- 粘贴后显示非空行数量；
- 空输入不能提交；
- 超过容量时提示具体限制；
- 不把用户歌单内容发送到分析或广告服务。

### 7.2 解析确认页

每条歌曲显示：

- 原始文本；
- 顺序号；
- 歌名；
- 歌手列表；
- 版本信息；
- 解析状态；
- 置信度提示；
- 编辑、删除和拖动操作。

页面还应提供：

- 解析成功、信息不完整、待确认、疑似重复的数量统计；
- 仅查看问题条目的筛选；
- 批量确认去重；
- 返回修改原始文本；
- 进入导出步骤。

### 7.3 导出结果页

包含：

- 目标平台选择；
- 导出条目数；
- 信息不完整条目提醒；
- 导出文本预览；
- 一键复制；
- 下载 TXT；
- 对应平台的官方导入操作说明；
- 返回继续编辑；
- 新建转换。

## 8. 状态定义

### 8.1 条目状态

| 状态 | 含义 | 是否允许导出 |
| --- | --- | --- |
| `PARSED` | 已识别歌名，其他字段无明显冲突 | 是 |
| `INCOMPLETE` | 歌手缺失或版本信息不完整 | 是，但必须提示 |
| `AMBIGUOUS` | 字段边界存在歧义，需要用户确认 | 用户确认后允许 |
| `DUPLICATE` | 疑似重复 | 是，但必须提示 |
| `INVALID` | 缺少歌名或内容无法识别 | 否 |

### 8.2 页面状态

- 空闲；
- 解析中；
- 解析成功；
- 解析失败；
- 编辑未保存到本地；
- 导出生成中；
- 复制成功或失败；
- 下载成功或失败。

## 9. 数据字段

### 9.1 解析歌曲条目

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `clientId` | string | 是 | 前端生成的临时标识，不代表平台歌曲 ID |
| `sourceIndex` | integer | 是 | 原始顺序，从 1 开始 |
| `rawText` | string | 是 | 原始行文本 |
| `title` | string | 是 | 歌名 |
| `artists` | string[] | 否 | 歌手或作者列表 |
| `version` | string | 否 | Live、Remix 等版本信息 |
| `status` | enum | 是 | 条目状态 |
| `confidence` | number | 是 | 0 到 1，仅表示解析置信度 |
| `warnings` | string[] | 否 | 面向用户的警告代码或描述 |

### 9.2 导出请求

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `provider` | enum | 是 | `QQ_MUSIC` 或 `NETEASE_MUSIC` |
| `tracks` | array | 是 | 按用户最终顺序排列的歌曲 |
| `includeIncomplete` | boolean | 是 | 是否包含信息不完整条目 |

## 10. 非功能需求

### 10.1 性能

- 500 首文本的纯规则解析目标在服务端 1 秒内完成，不包含网络请求。
- 编辑列表应使用适合大列表的渲染策略，避免明显卡顿。
- 复制和导出操作不得重新调用音乐平台服务。

### 10.2 隐私与安全

- 默认不持久化原始歌单和解析结果。
- 生产日志不得记录完整输入文本和完整导出内容。
- 不接收音乐平台账号密码、Cookie、Token 或二维码登录态。
- 不提供任意 URL 抓取入口。
- 所有文本在渲染时必须经过框架安全转义，不使用不可信 HTML。
- 限制请求体大小、条目数和单行长度。
- 隐私说明必须明确本地草稿的存储位置和清除方式。

### 10.3 可用性

- 移动端最小可用宽度按 360px 验证。
- 核心流程支持键盘操作。
- 状态不能只通过颜色表达。
- 错误信息应说明用户可执行的修复动作。

### 10.4 兼容性

- 支持当前主流版本的 Chrome、Edge、Firefox 和 Safari。
- 目标音乐客户端的导入兼容性必须以发布前实际版本验证结果为准。

## 11. 合规边界

1. 产品定位为用户文本整理和格式转换工具，不是音乐播放器或第三方账号管理器。
2. 不向公众提供歌曲音频、歌词、封面或播放地址。
3. 不声称能够解除会员、地区或版权限制。
4. 不使用未经授权的逆向接口、私有协议或登录凭据。
5. “官方可导入”必须有当前客户端实测依据；无法验证时使用“标准化文本”描述。
6. 页面不得使用易造成官方隶属关系误解的名称、Logo 或视觉设计。
7. 免责声明不能替代实际的技术和产品合规措施。

## 12. 验收标准

### 12.1 功能验收

- 给定文档中的所有格式样例，系统能正确拆分歌曲行。
- 用户能编辑歌名、歌手和版本。
- 用户能删除、拖动和确认去重。
- 缺少歌手的歌曲被明确提示。
- 导出文本顺序与确认列表一致。
- 一键复制和 TXT 下载可用。
- 刷新页面后可以恢复本地草稿，并可以主动彻底清除。

### 12.2 安全验收

- 网络请求和服务端日志中不出现音乐平台凭据。
- 服务端应用日志不记录完整歌单正文。
- 超过限制的请求被拒绝并返回明确错误。
- 页面不能通过歌曲文本注入 HTML 或脚本。

### 12.3 平台兼容验收

- QQ 音乐导出内容在指定实测客户端版本完成一次人工导入。
- 网易云音乐若标注“官方可导入”，必须在指定实测客户端版本完成一次人工导入。
- 验收记录必须包含客户端平台、版本、日期、输入样本、成功数和失败数。

## 13. 待用户确认事项

1. 正式前端基线是否遵循现有工程约定使用 Nuxt 4，还是改为纯 Vue 3 + Vite SPA。
2. Java 版本是否遵循现有工程约定使用 Java 17，还是改为 Java 21 LTS。
3. 网易云音乐第一版是否必须支持官方文本导入；若当前客户端不支持，是否接受只提供标准化文本或推迟该平台。
4. 单次 500 首的第一版容量是否满足预期。
5. 公开 QQ/网易云歌单链接解析是否确认延后到获得合法稳定数据源之后。
6. 产品正式名称、域名和免责声明主体。
